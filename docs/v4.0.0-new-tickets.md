# v4.0.0 執行期新發現 — post-v4 佇列

> **這個檔案是什麼**：v4.0.0 執行過程中（Wave 1–8）被發現的缺陷、票面前提更正、
> 以及任何「該修但不屬於 v4」的東西，全部集中在這裡，**依優先順序排好**。
>
> **鐵則：這裡的每一張都排在 v4.0.0 發版之後。** 沒有例外。
> 唯一的例外判斷在 `v4.0.0-execution-plan.md` §2.4：
> **「還沒做的波次裡，有任何一個依賴它嗎？」** —— 答案是「有」的票根本不會進這個檔案，
> 它會被排進那個波次。進到這裡就代表答案是「沒有」。
>
> **為什麼需要這條鐵則**：Wave 1 的**一條 lane** 就產出了兩張正式票。還有六個波次。
> 沒有它，每一波都會把自己的發現塞回 v4，**v4 永遠發不出去**。
> 這種範圍蠕變特別難擋，因為它**披著「這個發現很有價值」的外衣** ——
> 而它們確實有價值。有價值不等於屬於 v4。
>
> **與其他檔案的分工**：`docs/backlog.md` 是票的正本（完整票面在那裡）；
> 這個檔案只排**順序**，一票一行，不重複票面內容。
> 跟 `v4.0.0-execution-plan.md` 對 backlog 的關係一樣。

## 怎麼往這裡加一筆

### lane session 要做的（就這一件）

把發現寫進**你自己 lane 的 `.current/<lane>/pending-tickets.md`**（格式見 `docs/lane-protocol.md` §4；root `NEW-TICKETS.md` 已退役，E179）。
**不要自己配 backlog 票號，不要直接編輯這個檔案。**
（理由見 `v4.0.0-execution-plan.md` §2.4 —— 平行 lane 自己配號會撞。）

在回報裡點出**哪幾筆你認為值得提升成正式票**，以及為什麼。你最接近現場，那個判斷有價值。

### coordinator／整合者要做的

1. 先問 §2.4 那句話：**還沒做的波次裡有任何一個依賴它嗎？**
   - **有** → 排進那個波次，**不要**寫進這個檔案
   - **沒有** → 往下走
2. 配 backlog 票號，把**完整票面**寫進 `docs/backlog.md`（含 order row）
3. 在**這個檔案**加一行 —— 而且是**插進正確的位置，不是附加在最後**
4. `為什麼排在這個位置` 那一欄要寫出**相對於已有票的理由**，不是重複優先度標籤

### 排序的判準（由重到輕）

1. **會不會持續惡化？** —— 每經過一次 hop／一次 release 就更糟的，排前面
2. **失效是不是靜默的？** —— 會大聲失敗的排後面，因為它自己會提醒你
3. **誤導的對象是誰？** —— 誤導一個已經陷入困境的角色，比誤導一個順利的流程嚴重
4. **P 標籤** —— 前三項都打平才用它決勝

**不要只按 P 排。** P 是開票當下的估計，這個檔案有後見之明。
