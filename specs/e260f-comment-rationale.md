## test/e121-tasks-file-injection.test.mjs
The approved review report for the injection ticket is the spec this file executes. The trap: the pre-fix behaviour also returned `success: true`, so asserting no crash, `success === true` or `error === undefined` is not a test of the defect. What discriminates is (a) an `{error}` matching `/task_id must not contain a line break/` (or the matching field name for a payload guard), (b) `tasks.md` byte-identical to its pre-call content, (c) the forged id or marker absent from the whole file, (d) the row count from `parseTasksFromFile` unchanged, (e) no `.lock` artefact left behind (the guard fires before `withFileLock`). Every must-refuse case pins at least (a), (b) and (c).

Coverage floor, the review's eight must-refuse cells (field x mutator): `completeTask` taskId and note, `rollbackTask` taskId and reason, `voidTask` taskId and reason, `addTask` taskId and description. `addTask`'s taskId guard was the only live forging site before the taskId column was added, so it is not tested alone; all four mutators get a taskId case.

Explicit-refusal assertion: for complete, rollback and void with a line-break-bearing taskId, the file asserts positively on the `/task_id must not contain a line break/` message and negatively that it does not match `/not found|Could not find|No incomplete/i`. Without the negative assertion a test cannot tell a stated input-boundary invariant from incidental lookup-order safety (a newline-bearing id merely failing `Array.find`), and a refactor hoisting line construction above the `find()` call would go undetected.

Settled boundary: for row forging, LF is the whole class. Every line-splitting reader splits on LF alone: `parseTasks` (`migratedBody.split("\n")`), `addTaskInFile`'s duplicate scan and `voidTaskInFile`'s post-write invariant. `DEFAULT_TASK_REGEX` has no `m` flag, and `resolveTaskRegex` builds a custom pattern with no flags argument, so a configured `taskPattern` cannot add one. LF and CRLF forge at base and are refused now; CR is refused only as hygiene (it never forged anything, and the CR test does not assert forging). U+2028, U+2029, NEL, VT, FF and NBSP do not forge in either build.

Out of scope for the forging part: U+2028 and U+2029 make a row unparseable (erasure, not forgery), identical at base and working tree, filed as its own ticket (review finding R2-C2); the registry's `task_id: z.string().min(1)` schema, which the coordinator declined to tighten; SQLite mode, which uses parameterised SQL. Fixture helpers mirror `test/e117-void-task.test.mjs` (`mkWorkspaceWithTasks`, `readTasks`); its case for `voidTaskInFile` refusing a newline-and-`$&`-bearing reason passes unchanged.

Must-succeed set: no id containing a line break can round-trip through `tasks.md`, because `parseTasks` splits on `"\n"`, `DEFAULT_TASK_REGEX` captures the id as `(\S+)` (excluding `\r` and `\n`), and `.trim()` strips a leading CRLF's `\r` before the regex runs. The refused set is exactly the unrepresentable set, and no machine-derived id from `tw_sync`, `tw_detect_drift` or `getNextTask` is newly refused.

Line-separator cases: U+2028 and U+2029 are JS-only line terminators that `split("\n")` does not split on, but that `.` and an unanchored `$` cannot cross, so a row carrying one is a single line on disk yet unparseable. Part A is the input boundary: `containsLineBreak` widened to include both characters, reached from all eight call sites, the same field x mutator matrix, an input-boundary test not a forging test (they would silently erase the row if they reached disk). Part B is the parser: `parseTasks` fails loud on a row shaped like a live checkbox task row that carries one, defending a hand-edited `tasks.md`. A voided row carrying the same character must not throw: its invisibility is the `voidTaskInFile` contract, and `TASK_LINE_SHAPE_RE` excludes the void marker's `-` checkmark for that reason (review finding C2).

## test/e122-state-render-injection.test.mjs
Closes the state-render injection hole: `buildPromptForRole` used to `JSON.stringify` the live handoff state verbatim into every dispatch prompt, so any string leaf a role writes (`pending_notes`, `blocking_reason`, `scope_decision_why`, `dispatch_pins` values, `external_refs[].ref`) reached the next role's context unfiltered, and a quoted task-row checkbox or numbered SOP step header was indistinguishable to a structural scanner from authored content. Why a new hermetic file: `test/render-structure.test.mjs` covers the fix only incidentally, rendering against this repo's own live `.current/handoff.md`, so its one relevant assertion reds without the fix only while that repo's `pending_notes` happens to carry a quoted marker. Not re-tested: that file's detector soundness, and `content/**` (no fragment changed).

Spec-to-test map (the backlog row is the spec; mini-chain): the marker regex is the byte-identical union of the detector's two regexes ("regex union pin"); the transform is strictly additive, nothing deleted, reordered or truncated ("additive invariant"); adversarial marker shapes are neutralized ("marker coverage"); an already-quoted marker accumulates a second pair, cosmetic and accepted ("pre-quoted marker"); deep clone with no caller mutation, nested and non-string leaves preserved ("deep clone / leaf shapes"); the golden-capture separator constraint ("separator ordering"); the injection half is deliberately not closed and must not silently pass as closed ("NEW-8 (accepted, not a bug)").

Known, accepted, not tested: the null-leaf guard and the cycle-guard and non-plain-leaf branches are latent and unreachable through any real parse path (`asString` in `tools/handoff-parse.ts` turns every scalar into a string, and `parseDispatchPins` drops non-string pin values). `sanitizeForRender` is not exported, so unit-testing it would need an export (a source file, out of qa scope) or a hand-copied implementation (testing a copy, the vacuous-test failure this file exists to avoid). The fixture state is built via `writeHandoffState`, the real write path, with idioms shared with `test/dispatch-pins.test.mjs`. The regex-union pin extracts both regexes from live source text so it cannot go stale when either is edited. NEW-8: STRUCTURAL_MARKER_RE matches markdown structure only, so instruction-shaped plain prose renders untouched; the coordinator's recorded scope decision accepted this.
