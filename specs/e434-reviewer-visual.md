## Problem Statement

After E433 the served rules run the test-first chain, but the visual verdict still belongs to `qa-visual`, a sub-skill of qa-engineer that writes under qa-engineer's identity — and qa-engineer no longer judges, so nothing loads it. The whole visual comparison (capture, pixel diff, reading images, verdict) runs at one stop, and the served text still carries the retired visual loop: a `visual_round` cap, a `visual_split` threshold, the `visual_fail:` note and `VISUAL_ROUND_EXCEEDED`. This ticket renames the sub-skill and its template to `reviewer-visual`, loaded by code-reviewer (the chain's judge) only when the design declares baselines and pinned to opus; turns capture and pixel difference into executable checks qa-engineer writes and sr-engineer passes before hand-off, so `reviewer-visual` reads images only for a surface over its threshold; records an accepted over-threshold difference in the visual report's `## Allowed Differences` with its reason and no human stop; makes a visual rejection an ordinary code-reviewer rejection counted in `review_round`; retires the rule text of the visual counter and split threshold; points the PASS-time hints at the new sub-skill; and adds a migration note. Server behaviour, gate predicates, the transition table, schemas, counters and error-code count do not change; the old path keeps its counter until E435 / E420.

## User Stories

- As a code-reviewer on a design-armed feature, I want a visual sub-skill that I load only when the design declares baselines, so that the judge context owns the visual verdict and non-UI features pay nothing.
- As a qa-engineer, I want my SOP to tell me to write the capture and pixel-difference checks for every baseline surface, so that sr-engineer sees a visual miss while building, not at the last stop.
- As an sr-engineer, I want to know that a difference that shrinks on every try is progress and when to stop, so that I neither give up early nor loop forever.
- As a human, I want an over-threshold difference the judge accepted to be listed with its reason, so that I can disagree later without the ticket stopping for me now.
- As an adopter upgrading, I want a note that the old override file and template name are no longer used, so that a stale `qa-visual` file does not silently keep old rules.

### R1 — over-threshold flow (needs human ruling)

Rulings in tension: §14.2 ruling 15 (within threshold the executable check decides; over threshold `reviewer-visual` reads and decides; a baseline comparison never stops a ticket), ruling 16 (an accepted difference passes with no human stop), §16.1 ruling 7 (a difference that stops shrinking "halts under §5's fix-try cap"), and §5 itself (`fix_try` cap → "STOP … wait for human instruction"). Ticket (2) says sr-engineer "must pass" the checks before hand-off.

Worked example. Feature `e470-settings-screen`, surface `settings.language`, declared threshold 0.5 % over its compare region. sr-engineer's tries measure 2.1 % → 1.2 % → 0.9 % → 0.9 % → 0.9 %. The remaining 0.9 % is sub-pixel text anti-aliasing.

- **(a) Recommended — over threshold is a measurement, not a red.** The diff check fails only when it cannot measure (no tool, no image, dimension mismatch); an over-threshold surface is recorded `over`. sr-engineer keeps trying while it shrinks (2.1 → 1.2 → 0.9 is progress, not the same failure); the two tries at 0.9 % use the `fix_try` cap (2), so sr stops fixing that surface and hands off naming `settings.language 0.9 % (threshold 0.5 %)`. code-reviewer loads `reviewer-visual`, which reads only that surface's two images, sees anti-aliasing, records it `accepted` with the reason in `## Allowed Differences`; PASS; no human stop. Had it been a missing selection bar: `CHANGES_REQUESTED` → sr-engineer, `review_round` 1. Text cost: `const09.body` carries the §5 carve-out for this case (a constitution fragment, so no skill overrides the constitution).
- **(b) Over threshold is a red; §5 applies literally.** The diff check fails at 0.9 %; at the cap sr stops `Blocked` and waits for a human. `reviewer-visual` would read images only after a human resumes — a baseline comparison now stops the ticket, against rulings 15 and 16.
