# e260e-comment-rationale

Rationale cut from long comments in the owned test files of lane e260e (see `specs/e260e-test-comments-a-d.md`). One H2 section per source file, named after the file, added by the qa-engineer when a trim moves rationale here. A comment keeps at most a one-line pointer to this file.

## test/_e123b9-crash-worker.mjs
The worker calls `readHandoffState(workspacePath)` once against the built `dist/` output, the actual own-workspace read entry point the migration runs inside. The fault-injecting fs shim and its loader make a real `process.exit(137)` happen partway through the rename sequence: a genuine OS-level crash, not a simulated one. If the configured threshold is never reached (a fixture with fewer renames than expected, a test-authoring bug) the migration completes and the worker prints `CRASH-WORKER-DID-NOT-CRASH`, so the parent's exit-code assertion fails loudly with a clear cause instead of a silent false pass.

## test/_e123b9-fault-fs-loader.mjs
Uses Node's stable `module.register()` hook API, registered through `node --import 'data:...register(...)'`. It redirects only the bare `fs` specifier, the exact form every module under `dist/` imports (`import * as fs from "fs"`, tsc NodeNext/ES2022 output). `node:fs` is deliberately not intercepted, which is also how the shim reaches the real implementation without re-resolving to itself. This is standard Node fault-injection plumbing, not a mock of production code: every `dist/` module runs unmodified, and only `renameSync` gets a thin counting wrapper around the real syscall.

## test/_e123b9-fault-fs-shim.mjs
Purpose: a real child-process crash mid-migration, leaving the per-lane lock stale. The loader redirects the bare `fs` specifier (as used by `tools/lane-migrate.ts` and every other `dist/` module) to this file. It re-exports every real fs export except `renameSync`, which counts calls and, at the threshold, exits 137 immediately after the real rename completed: no unwinding, no `finally` blocks, exactly what a killed process does. The env var `CRASH_AFTER_RENAME=<n>` is set by the parent test before it spawns the crash worker; unset means no fault injection.

## test/_e123b9-migration-worker.mjs
Mirrors `test/_lock-worker.mjs` (a tiny argv-driven worker spawned by `node --test`), and promotes the reviewer's scratch verification technique into a durable qa-owned fixture. Workers busy-wait until the same `startAtEpochMs` so real fs and lock work overlaps in wall-clock time. A write is `readHandoffState` plus `writeHandoffState`, mirroring a real `tw_update_state` pre-flight-then-write shape. Output tokens: `R-ok` / `R-missing` (read completed, exists true/false), `W-ok`, or `ERR <mode> <message-prefix>`. It never throws uncaught, so the parent's `spawn(...).on("exit")` always fires cleanly.

## test/_e123b9-round2-migrate.mjs
Exercises the wired trigger exactly as a real `tw_get_state` call would: import the built `dist/tools/handoff-parse.js` and call `readHandoffState(scratchWorkspacePath)`, the own-workspace entry point the migration is wired into. Run as a child process, never imported, so its module graph and `guards/session.ts` in-memory state are fully independent of the calling test process.

## test/compose-equivalence.test.mjs
Spec-to-Test map (ticket A9, compose-not-strip): lite equivalence (AC2) is covered by the four lite fixtures (non-design and design, each also with fullDetail); full non-design equivalence (AC3) and full design-armed equivalence (AC4) each by a normal and a fullDetail fixture; AC5 (fullDetail) by the four `-fd` fixtures across design/non-design and lite/full; AC7 (stripOriginTags keeps working) is implicit in every fixture, because the goldens were captured after stripOriginTags landed and before compose-not-strip; AC8 (single source of truth) by the test that concatenating the 15 manifest fragments reproduces the retired monolith byte for byte (literal concatenation, no normalization, DR-1 Option R); AC9 (hook byte-equivalence) by the lite and full hook tests; the rationale section refs by the forward-resolve and sections-exist-in-fragments tests.
WHY: that composition is behavior-preserving, not just cleaner, is an empirical claim code inspection cannot prove. The tests replay the current code path for every captured dispatch mode and assert strict byte equality (no normalization) against snapshots from the pre-refactor strip pipeline (`scripts/capture-constitution-golden.mjs`, committed at `test/fixtures/compose-golden/`). A later edit to `prompts/constitution-manifest.ts`, `prompts/build.ts` or `bin/agent-governance-context.mjs` that changes what a mode emits is caught here, not only by reading the diff.

## test/config-cache.test.mjs
Spec-to-Test map: AC-4 (same-process content and mtime bump becomes visible without restart) by the content-mtime-bump, driftbaselineids-append and fast-path tests; AC-5 (absent, create, delete, recreate transitions with no crash and no stale positive or negative caching) by the full-transition-cycle, repeated-absent-reads and existence-flip-beats-mtime-equality tests.
WHY: before the invalidation fix, configCache was set once and read many with no invalidation path, so a post-release driftBaselineIds append (a release-engineer SOP step) stayed invisible to tw_detect_drift until the server restarted. The tests pin the "re-stat every call, compare existence and mtime" contract so an "optimize away the stat" refactor cannot reintroduce the stale-forever cache. Unlike `test/config-versioning.test.mjs` (fresh workspace per test), these reuse one workspace across several loadConfig calls, the only way to exercise the cache hit or miss decision. `fs.utimesSync` pins exact mtimes (round-trip exact on the filesystem used) so assertions do not depend on wall-clock gaps.

## test/dependency-overrides.test.mjs
Spec-to-Test map: AC1 and AC4 of the protobufjs/qs spec map to these tests (override pins must stay and meet the patched-version floor). AC2 (embedding runtime) and AC3 (suite green) are verified by the audit, a manual embedding smoke and the full suite, not re-run here, since a real embedding test needs network or a model download and is unfit for the headless suite. E57 AC1/AC2 (sharp floor, SDK and transformers pins unchanged) map to the sharp tests; AC5's reachability narrative is prose.
WHY: the advisories reach the tree only transitively, so the fix is a package.json `overrides` pin and nothing else encodes it; a dropped pin would silently bring the vulnerabilities back until the next manual audit. Duplicate-key guard: the first edit adding the sharp override created a second top-level `"overrides"` key; `JSON.parse` keeps only the last duplicate, so a parsed assertion could not catch it, and only a raw-text check for exactly one `"overrides":` key can. It was caught in review only by a version mismatch.

## test/drift-stamp-advisory.test.mjs
Contract (feature e9a-stamp-integrity, AC3/AC4): DriftReport gains a purely additive top-level `stampAdvisory: string | null`. Non-null when `handoff.last_updated` matches `/T\d{2}:\d{2}:00\.000Z$/` (the five hits confirmed in `research/e9a-stamp-forensics.md`, round-hour and half-hour included as a subset); null otherwise, including on every pre-handoff early return. `driftDetected`, `details`, `tasksCompleted` and `tasksIncomplete` must be identical to what they would be without the field. Tests mirror `test/drift-baseline.test.mjs` and `test/drift-archived-tasks.test.mjs`, and avoid the live tw_detect_drift tool because the running server may hold a stale pre-rebuild dist. tasks.md must begin with `<!-- schema_version: 1 -->` so checkVersionSkew and parseTasks() do not short-circuit before the stampAdvisory computation.

## test/ac-execution.test.mjs
Gate family: `gates/ac-execution.ts` is the fourth member of the evidence-existence gate family (MISSING_EVIDENCE, VISUAL_EVIDENCE_MISSING, EXPECTED_RED_DIFF_MISSING). PM annotates provable ACs with a `proof:` line; qa-engineer executes each declared proof at Phase 3.5 and records the run under a `## AC Execution Log` H2 in `qa_reports/review_<id>.md`; the server checks only that the section exists (never runs proofs, never parses output).
Placement: the architecture names `test/gates/ac-execution.test.mjs`, but `npm test` runs `node --test test/*.test.mjs`, a non-recursive shell glob, so a file in a `test/gates/` subdirectory is silently never collected (verified with a probe file). The architecture's cited precedent `test/gates-expected-red.test.mjs` is itself flat. Filing at the nested path would ship a test that never runs under CI, a test-infra defect within QA's Phase 3 authority, so the file is flat; the disposition is in `qa_reports/review_T-E3-QA.md`.
Spec-to-Test map: AC1 (proof: schema) verified by grep during QA, not re-tested; AC2 (conditional proof) and AC3 (Phase 3.5 heading) by skill-content assertions; AC4 arm check (hasProofAnnotatedAC) U1-U6; AC4 disposition check (hasAcExecutionLogDisposition) U7-U14; AC4 PASS gate composition I1-I3b; AC4 covers: batch coverage U10, U11 (unit level only); AC5 dormant when unarmed or no spec file U3, U4, I3, I3b; AC5 file-mode only I5; AC6 Phase 4 FAIL cross-reference, no new escalation row, a skill-content assertion.
Integration "I4" note: recordReviewInFile (`gates/qa-review.ts`) unconditionally creates or appends review_<id>.md for every id in completed_tasks on a qa_review-bearing write, before the gate check. A PASS'd id therefore always has a direct file, so the covers: fallback is unreachable at the integration layer; an attempted test hit AC_EXECUTION_LOG_MISSING because the direct, H2-less file takes precedence over another id's covers: file (the contract U12 pins). This matches `test/gates-expected-red.test.mjs`'s own I4, which tests "at least one of two PASS'd ids has the H2".
Escalation Routes row count: one row per documented situation. AC6 adds no row for AC-execution failures (Phase 3.5 reuses Phase 4 FAIL); the table grew from 6 to 7 rows for an unrelated reason, a `contract defect | Blocked | ... | pm` row (E46, 2026-08-10) giving QA a status other than FAIL for an approved spec or design divergence. The pin stays at the current count so a later accidental add or removal fails; bump it with a comment naming the ticket on the next real addition, never silently to make an unrelated diff pass.
