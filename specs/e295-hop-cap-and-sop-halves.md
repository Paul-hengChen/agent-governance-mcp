# e295-hop-cap-and-sop-halves

Lane e295 of the post-v4 wave 2 fan-out (`specs/fanout-post-v4-w2.md`, the single content lane). Tickets: E295 items (1)(2); E298 items (2)(3)(4)(6)(7) (the SOP half — items (1)(5) shipped in wave 1); E299's one 5c sentence; E300's content half (one coord-02 sentence plus the matching `gates/registry.ts` row); E301 (option chosen by the human at cut time). Scope is the lane row in the manifest; it is not widened or narrowed here. Base `25bc84c`.

## Problem Statement

Five small content changes are blocked on one another only by the shared-artifact rule (`content/**` is edited by one lane per wave), so they ship as one lane. (E295) The `hop` cap of 10 fires before the `review_round` / `qa_round` caps can on any lane that has an architect hop plus two review and two qa rounds (that chain lands exactly on 14), so the same loop is bounded twice and the stricter bound has no loop semantics; the one escape used so far — a same-lane follow-up feature `<feature>-r<n>-fix` — is an unwritten precedent (`specs/fanout-e260.md` Decisions 2026-10-01 / 2026-10-02) that costs a lease wait each time. The cap's own landing edge `(pm, In_Progress)` is also unreachable from `code-reviewer:In_Progress` and `qa-engineer:In_Progress` at the cap (E41, re-verified on the compiled `validateTransition` at cut time: `TRANSITION_REJECTED`, while the same landing under `QA_ROUND_EXCEEDED` is accepted). (E298) The integrator SOP still verifies lane and integration branches with local full-suite reruns although `ci.yml` has triggered on `feat/**`, `integ/**` and `release/**` pushes since wave 1 and `scripts/verify-release.mjs --ci-check --sha` already reads a run's verdict. (E299) 5c does not name `npm run check:bookkeeping`, which has been in `npm test` since wave 1. (E300) The `dispatch_pins` tier enum and its rejection code `DISPATCH_PIN_TIER_REJECTED` are enforced by the server but no `content/*.md` names the four values or the code, so the registry row is the only `documentedInProse: false` entry. (E301) The Evidence-Citation Convention asks a row to cite an archive folder that release step 7a names only at release time (and names after the releasing feature, `release-vX.Y.Z`, not the citing lane); 22 live citations are tolerated by `check:bookkeeping` with a note today and every one of them becomes a failure at the next release's 7a move, which would turn the release pull request's CI red.

## User Stories

- As a lane session, I want the hop cap at 14 and a written, conditioned same-lane continuation, so that a chain that is still inside its review and qa caps can finish without an ad-hoc ruling or a lease wait.
- As the coordinator reading `HOP_CAP_EXCEEDED`, I want the `(pm, In_Progress)` landing to be accepted from every state, so that "frozen at PM" means the same thing the three round caps mean.
- As the integrator, I want 5a and 5b-6 to read CI on pushed branches, so that N lanes verify in parallel and a local-green/CI-red divergence (E228) is caught before the wave pull request.
- As the integrator, I want 5c to point at `check:bookkeeping` before the bookkeeping commit, so that a wrong done-mark is caught locally instead of by the pull request.
- As a coordinator persisting a model pin, I want the SOP to name the four accepted tier values and the rejection code, so that the first rejection is not the first time I see the rule.
- As the release-engineer, I want evidence citations that stay valid across the 7a move without me editing other tickets' rows, so that the first run of the rewritten release SOP is not blocked by bookkeeping.
