# e232-leak-cleanup

## Problem Statement

This repo's tracked tree cannot go public yet: role-authored durable content (specs,
qa/review reports, research notes, the CHANGELOG, a handful of comment-only source
files) still carries three classes of information the constitution's §6 *Information
hygiene* rule bans from every durable output — an employer-internal URL / work-item
link, a third-party client's private codename, and an absolute local path that exposes
a username. A prior cleanup pass (`specs/decodename-cleanup.md`) already genericized
the codename out of the five **always-loaded** prompt fragments, but deliberately left
the named specifics in provenance-only docs (`research/`,
`content/constitution-rationale.md`) on the reasoning that those files are never
injected into a prompt. That reasoning no longer holds once the repo itself is a
public artifact: a provenance doc that is merely uncomposed is still tracked and still
public. Separately, one research filename carries the codename directly, and the
`content/constitution-rationale.md` paraphrase of the Generic-citation exemption list
drifted from the normative bullet during E231's review (round-1 code review, recorded
finding, non-blocking at the time) — a decision was made to fix it in a follow-up
rather than block E231's ship.

This ticket (E232) is scoped to the classes lane e232 owns per the fan-out manifest's
Decision R2: **role-authored content only**. Protocol-generated content (lane
handoffs' `prd_path` etc., the fan-out manifests' worktree column, and the two test
fixtures derived from them) carries the same local-path class but regenerates on the
next tool write — that cleanup is E235's job (a format fix first, then a retroactive
pass), not this ticket's.

## User Stories

- As the human maintainer deciding whether this repo can go public, I want every
  role-authored tracked file free of employer-internal links, the third-party client's
  codename, and local usernames, so that flipping repo visibility does not re-expose
  the class of leak that already cost three months of public exposure once (backlog
  E104).
- As a future contributor reading `content/constitution-rationale.md`, I want its
  Generic-citation paraphrase to name the same artifacts the normative bullet exempts,
  so that the rationale does not read as narrower than the rule it explains.

## Acceptance Criteria

Three leak-class patterns are tracked outside this repo (not quoted here, per
constitution §6 — a spec is itself a durable output): `$TMPDIR/e232-leak-patterns.txt`,
one line per class, TAB-separated as `<class_id>\t<extended-regex>` (a class's own
regex may itself contain `|` for alternation, hence TAB not `|` as the field
separator), class ids `class1_internal_url`,
`class2_client_codename`, `class3_local_path`. Every proof below reads that file rather
than a literal in this spec. If the file is missing, reconstruct each pattern from its
class description below by inspecting the cited pre-fix example location(s) directly
(each one is presently a real, on-disk hit) — never by asking another role to say the
literal out loud.

  (e.g. "the internal work-item tracking this decision") plus, where the surrounding
