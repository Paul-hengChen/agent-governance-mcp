## Problem Statement

After E432 the server accepts both chains, but every rule it serves still describes the old one: the constitution gives PASS and `tw_complete_task` to qa-engineer and draws `pm → architect → sr-engineer ↔ code-reviewer → qa-engineer`; the qa-engineer SOP reviews the implementation and writes PASS; the sr-engineer SOP has no return route to qa; the code-reviewer SOP hands APPROVED to qa; pm, architect and coordinator route to sr-engineer (an edge the test-first overlay closes); release-engineer, doc-writer, integrator and the dispatch template wait for a qa PASS; the shipped qa template is pinned to sonnet. This ticket switches the served text to the test-first chain ruled in §14.2 — pm → (architect) → qa-engineer writes the scenario tests → sr-engineer builds to them → code-reviewer judges both and writes PASS — and removes the superseded old-chain text in the same change, so no composed bundle carries both. Server behaviour, gate predicates, the transition table, schemas, error codes and counts do not change; the old path stays in the server until E435.

## User Stories

- As a qa-engineer subagent, I want my SOP to tell me to write one test per ticket scenario against the public interface and to decide and record the interface details the scenarios leave open, so that sr-engineer has an executable definition of done.
- As an sr-engineer, I want my SOP to say I build to the pre-written tests, may not edit them, and how I send a contradictory test back or stop an unbuildable scenario, so that I never guess or rewrite the definition of done.
- As a code-reviewer, I want my SOP to make me the judge of both the tests and the implementation and the writer of PASS, so that the role that wrote neither decides.
- As a pm / coordinator, I want routing, the marker, the architect-before-qa placement and both loop counters stated, so that a feature enters the new chain without a `TRANSITION_REJECTED`.
- As a human reading the composed prompts, I want no instruction that still names qa-engineer as the judge, so that the rules and the server agree.
