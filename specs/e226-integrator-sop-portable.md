# e226-integrator-sop-portable

Lane `e226` of `specs/fanout-post-v4-w9.md` (post-v4 wave 9). Tickets: E226 + E349 + E350. Text-only wave: no code, no config, no `dist/` change.

## Problem Statement

The integrator SOP (`content/skill-integrator.md`) can be called in any workspace, but it calls agc's tools by repo-relative path (`node scripts/<x>.mjs`). That path only works when the workspace is the agc checkout itself. The scripts do ship with agc: `package.json` has no `files` field, so the install holds the whole tracked tree. This corrects the premise of E226. The real gap is the call form. E290 set the generic form in `docs/lane-protocol.md` §5 (`node <agc 安裝位置>/scripts/fanout.mjs`, and the repo addendum may give its own call). Not every tool works under that form: `scripts/verify-release.mjs` (the CI verdict) and `scripts/check-bookkeeping.mjs` find their root from their own location (`import.meta.url`), so run from an agc install in an adopter they check agc's own repository, silently. The SOP also states this repo's facts as if they were generic (E349): the shared-artifact list, `npm run build` / `npm audit` / `dist/`, `npm run check:bookkeeping`, `verify-release.mjs` as the CI verdict, and `node bin/agc-init.mjs`. Its 5a evidence and new-findings rows only describe `artifacts: repo`. Under `artifacts: local` the lane cannot commit those paths (D2 = (i)). The same repo-relative `node scripts/fanout.mjs check --cut` call also appears in the PM SOP, constitution §3.1 manifest tier condition 3 and the coord-03 manifest-tier writer action (E350).

## User Stories

- As an adopter's integrator, I want every agc tool call in my SOP written against the agc install, so that I can run the SOP in a workspace that is not the agc checkout.
- As an adopter's integrator, I want every CI verdict written as the repo's CI check, with what it must prove and a `gh` fallback, so that I never check agc's own CI by mistake.
- As an adopter's integrator, I want the repo-specific commands and lists (shared artifacts, build, CI check, bookkeeping check, `agc` call form) to come from my repo's addendum, so that I never run this repo's commands in mine.
- As an integrator in an `artifacts: local` workspace, I want the 5a evidence and new-findings checks to tell me where to read files the lane could not commit, so that I can verify a lane without sending it back for something it cannot do.
- As a lane PM / coordinator in an adopter, I want the `fanout.mjs check --cut` call in my SOP and constitution written against the agc install, so that the manifest-tier check can run.
- As this repo's integrator, I want the addendum to give the repo-relative call for every agc tool the SOPs call, and this repo's CI check, so that this repo keeps working unchanged.
