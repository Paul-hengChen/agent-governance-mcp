## Correctness
No `required` findings.

- **Fence-closure math re-derived independently** (not just trusting the spec's own reasoning): wrote a standalone CommonMark-shaped closability checker and ran it against `renderDataBlock` output for 11 adversarial bodies — exact-length run (N=3), longer run (N=5, N=10), run at line-start, run at line-end, CRLF-terminated fence-shaped line, an embedded tilde fence (`~~~`), a 3-space-indented backtick run, a JSON-escaped multi-backtick note, a raw markdown RAG-chunk body containing a fenced block plus an imperative sentence, and a run glued to surrounding text with no isolated line. Every case: fence adapts correctly and no line in the body can close the block. This is because `longestBacktickRun` scans raw characters without regard to line position, indentation, or line-ending style, so the fence-length invariant (`fence > longestRun`) holds unconditionally — a genuinely robust property, not merely "handles the cases the author thought of."
- `bin/agent-governance-context.mjs:197`: the `!stateRenderer` check is added to the existing four-way `||` guard correctly; a partial `dist/` (e.g. `handoff-parse.js` present but `build.js` missing its new exports) correctly falls through to `loadStateRenderer`'s `catch` → `null` → the misconfigured-hint branch, never a raw fallback. Verified by code inspection; the destructuring of `buildMod.renderHandoffStateBlock` etc. would be `undefined` (not throw) if the export were missing under a stale-but-present `build.js`, but `stateRenderer` itself would still be non-null in that specific pathological case (stale dist with old exports) — `recommended`, not `required`, since a stale-but-successfully-imported `dist/` after `npm run build` cannot occur on the same commit, and existing sibling call sites (`composeConstitution`, `composeSkillText`) have the identical pre-existing shape.
- `renderStateLookupFailedBlock` (prompts/build.ts:172-183): `body: error.message` is bounded correctly. Cross-checked with a real js-yaml malformed-frontmatter throw and a real `HANDOFF_LAYOUT_CONFLICT` throw — both land fully inside the fence with an adaptive length, no leak.
