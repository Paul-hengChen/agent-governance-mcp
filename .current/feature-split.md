- **Sequencing hazard in plan §6's T-E123-01 wording.** "Migration runner, no read-point changes" is only safe if the runner is **not auto-invoked**. `readHandoffState` heal-writes lazily migrate on first read. If E123a moves the flat files into `.current/<lane>/` while every reader still resolves flat paths, `main` breaks between E123a and E123b. E123a must ship the runner + reverse runner + schema constant **unwired** (plus a path resolver that still returns flat paths). E123b flips it.
- **`task_size` budget.** E123b's ~31 call sites exceed one sr-engineer task. It has to be cut into ≤5-file tasks inside the ticket. That costs tasks, not hops: one chain, one review round, if the resolver makes each site mechanical.

## Decisions — SETTLED by the human, 2026-09-23 (split approved; D1–D3 taken as the coordinator recommended)

- **D1 lane name**: `.config.json` explicit key (E73, later) → `feat/<id>-*` branch → **`_primary`** for primary / `main` with no ticket id. Migrating a flat `handoff.md`: lane = the ticket id parsed from its `active_feature` (`e163-ci-gate-ordering` → `e163`); unparseable → **`_legacy`**.
  - **AMENDED 2026-09-23 (J2 cut, human-approved)**: a flat `handoff.md` migrates into the **runtime lane**, `resolveCurrentLane(ws)` (branch `feat/<id>-*` → id, else `_primary`), NOT the ticket id parsed from `active_feature`. Otherwise a workspace on `main` would migrate its state into `.current/<ticket>/` and then read `.current/_primary/`, and look empty. `resolveLaneName` survives only in F0's own tests. The lock is per-lane (`.current/<lane>/.handoff.lock`); `.current/archive/` stays workspace-wide.
- **D2 + D3/E157 — package A′ + monthly grouping** (amended by the human 2026-09-23, superseding plain A): at **lane close** (before merge, inside the lane, so the PR carries the move), `.current/<lane>/` is moved **unchanged, raw files kept** to `.current/history/<YYYY-MM>/<lane>/` (YYYY-MM = the close date). It stays tracked in `main`, so the top of `.current/` only ever holds live lanes. The move mechanism must exist in adopter workspaces (E73 `agc feature finish` or E125 writeback), never release-only. `.current/archive/` is **gitignored**. E132's `getLaneFeatureHistory` is re-pointed at live lanes + `history/` (F1-owed). Rejected alternatives: plain A (unbounded top-level dirs); B (delete at writeback + tracked archive with retention); a lossy per-lane summary `.md` (irreversible — A′→summary compaction stays possible later, the reverse never is). PR/commit links for history are a post-v4 ticket.
- **E99 — per-hop durability** (human 2026-09-23): the handoff fields stay transient, AND every write carrying them appends one record to a per-lane sidecar, because `handoff.md` keeps only the last hop and the history would otherwise lose every earlier one.
- **Workspace-wide, not lane files** (human, 2026-09-23, F1 integration): the role SOP override files `tools/role.ts` reads from `.current/`, and `.current/.agc-hook-marker.json`. Both are policy/config, like `.config.json`/`exemptions.json`, and per-lane copies would diverge silently. `LANE_FILES` does not grow for them.
- **E125 re-scope**: drop its snapshot-to-archive half; keep the `tasks.md`/backlog writeback half.
- **Open for F0's PM**: which E99 option. The coordinator's position is (i) plus the reported tier: `dispatch_mechanism` + the self-reported tier, with no new retro surface (that is option (ii), out of scope).

## Original framing of the cut decisions (kept for the record)

- **D1 lane name**: explicit `.config.json` key (E73, later) → `feat/<id>-*` branch → ticket id (`e123a`) → fallback. The fallback for primary on `main`, and for a flat `handoff.md` whose `active_feature` has no parseable id, is still **open**.
- **D2 lane-dir lifecycle after merge**: delete from tip at E125 writeback (history survives in `git log`), or keep under an archive path. This interacts with D3/E157.
- **D3 / E157 `.current/archive/`**: track / gitignore / track + retention. Note that E132's `getLaneFeatureHistory` reads this dir. If lane dirs are tracked (E123's premise), per-lane history may move there and make the archive redundant.
- **E125 re-scope**: its snapshot-to-archive half is largely redundant once lane history is tracked. Its `tasks.md`/backlog writeback half is still owed.
